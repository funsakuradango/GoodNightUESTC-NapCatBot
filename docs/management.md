# 管理页面

独立管理台提供学校账号配置、学校短信验证浏览器、微信扫码授权及运行状态。沿用已有 Python 任务逻辑与数据卷，不提供手动签到或发送 QQ 消息的管理接口。

## 为什么使用独立页面

2026-10-28 在实际部署的 NapCat v4.18.37 上验证发现，其加载器以 `not in official plugin whitelist` 拒绝第三方插件。虽然官方文档介绍 WebUI 扩展接口，该版本不能直接安装此自定义页面。部署者已选择保留现有 NapCat 版本，使用独立管理台；未修改白名单或替换 QQ 客户端。

## 页面能力

- 保存学校账号密码、检查会话、尝试一次账号密码登录；密码留空保留原值，接口不回传密码。
- 首次学校登录或再次出现短信验证时，启动服务器上的官方登录浏览器，由本人完成短信验证码并信任环境。学校验证入口最多开放 10 分钟。
- 微信首次授权时显示短期应用宝二维码，手机微信扫码后等待结果并隐藏二维码；已有有效授权时直接复用。授权失效时先按原运维流程处理缓存，页面不会主动删除现有微信授权。
- 查询本地今日记录、最近管理操作及原有调度时间；即时暂停或恢复每日调度，取消当前管理操作。

此版针对已有的单账号部署，不支持在同一 profile 中直接更换学校账号。已有微信授权不因测试页面被清除；免扫码成功与首次扫码页面应分别验证。

## 部署

服务器 `.env` 添加：

```dotenv
# 至少 32 字符的随机私有 API Token，不发送给浏览器
MANAGEMENT_TOKEN=<随机私有密钥>
# Docker 网络内实际可达的已有 NapCat WebUI 地址，区别于 OneBot API
NAPCAT_WEBUI_URL=http://napcat:6099
BOT_NETWORK=<已有机器人网络>
```

构建与启动管理服务。与 scheduler 共享同一项目名和数据卷；已有 cloud 部署还需添加 `-f compose.cloud.yaml`。不启动旧的 debug 服务，避免占用同一个 6080 端口。

```bash
docker compose -f compose.yaml -f compose.napcat.yaml -f compose.management.yaml build management
docker compose -f compose.yaml -f compose.napcat.yaml -f compose.management.yaml up -d --no-build management
```

scheduler 和 cli 也必须升级到包含 `app/settings.py` 的版本，才能读取网页保存的配置。升级时先备份 `.env`、源码与数据卷，按原部署流程测试后重新创建 scheduler；单独安装页面无法让旧程序获得即时配置能力。管理镜像使用 debug 构建阶段中的 Xvfb、VNC 和 noVNC，无需引入额外 Python 或前端依赖。

## 访问与身份验证

默认管理台仅绑定服务器 `127.0.0.1:6081`，学校验证浏览器仅绑定 `127.0.0.1:6080`。沿用 SSH 隧道：

```bash
ssh -N -L 6081:127.0.0.1:6081 -L 6080:127.0.0.1:6080 user@server
```

打开 `http://127.0.0.1:6081/`，使用本人现有 **NapCat WebUI Token** 登录管理台；若 NapCat 开启两步验证，同时输入动态验证码。这里不是学校密码，也不是 OneBot HTTP Token。后端向配置的 NapCat `/api/auth/login` 验证身份，不改动 NapCat 配置，不发送 QQ 消息。

验证成功后使用一小时有效的随机 HttpOnly、SameSite=Strict 会话 Cookie；原始 Token 不保存到浏览器存储。服务重启后需重新登录。登录有频率限制，管理操作检查同源请求，并拒绝跨域请求。Python API 的独立 Bearer Token 仅供服务端操作，不能放入静态资源。

此版通过可信 SSH 隧道使用 HTTP；不要直接开放公网或按本文原样配置到公网反向代理。若未来提供 HTTPS 访问，需要同步配置安全 Cookie、代理边界及校验，不能仅修改端口绑定。

## 首次学校验证

先保存学校账号密码，点击「启动学校验证浏览器」，稍候再点击「打开验证浏览器」。在服务器上的学校官方页面完成短信验证码与信任环境。验证浏览器在新标签页打开；仅在管理操作期间运行 Xvfb、VNC 和 noVNC，完成、取消或超时后关闭。

6080 仅绑定服务器回环地址，复用 SSH 管理边界；浏览器入口不单独提供密码，必须使用受信任的单用户服务器与 SSH 隧道，不能反向代理为公开页面。再次触发学校风控时仍需人工验证，不保证永久免短信。

## 配置、状态与副作用

网页配置原子写入数据卷中的 `settings.json`（0600），只允许学校账号、密码和调度开关；优先级高于 `.env`。`.env` 继续作为部署配置和未设置字段的默认值。后续在 `.env` 修改已被网页覆盖的字段不会生效，应在页面修改，或停服务后审慎处理对应覆盖字段。

密码与原 `.env` 一样保存在受控文件中，不承诺磁盘加密；备份该文件时按凭据处理。`admin-last-job.json` 只保存已过滤的管理结果，不保存密码、Cookie、code 或 ticket。微信凭据继续沿用原加密存储。

所有管理操作和设置保存都检查共享 `task.lock`，与 cli、scheduler 和旧 debug 互斥。保存配置即时生效，scheduler 每轮重新读取调度开关，后续 CLI 进程读取最新账号密码。暂停调度不取消已在执行的业务任务；「取消」仅作用于当前管理操作。现有通知补发机制继续运行。

页面今日记录来自本地状态文件，不代表实时官方查询结果；登录前失败可能没有当天业务记录。已有 `scheduled_date` 不会因恢复开关或服务重启而清除，避免自动重复提交。登录、微信授权与只读检查均禁用通知，管理服务没有 `run` 接口。

## 回滚

停止 management 即可移除管理台。回滚 CLI / scheduler 旧版本前，先核对网页覆盖配置是否需要同步回私有 `.env`，尤其是调度暂停状态；旧版本不会读取 `settings.json`。保留每日状态和原 profile，不用恢复旧数据卷来回滚代码。
